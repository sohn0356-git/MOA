# 묵상 작성 중 새로고침과 내용 유실 조사

확인 기준: main d537d657d5d82f8a2bcfcfe7d0579b3aa90c6f05.

기존 main.tsx는 60초 간격으로 업데이트를 조회하고 onNeedRefresh에서 updateServiceWorker(true)를 즉시 호출했다. sw.ts는 install에서 skipWaiting하고 activate에서 열린 /MOA/ 탭 전부에 client.navigate(client.url)를 실행했다. 새 배포가 작성 중인 탭을 강제로 재시작할 수 있는 경로가 확인됐다. 묵상 작성 상태는 React 메모리에만 있어 재시작 때 사라졌다. 실제 사용자 사건의 시각별 브라우저 로그는 없어 해당 사건이 이 경로에서 발생했다고 단정할 수는 없다.

변경:
- 네이티브 서비스워커 등록은 새 버전을 알리기만 한다. 사용자가 업데이트 버튼을 누른 창만 승인 후 reload한다.
- SW 설치 시 skipWaiting/전체 탭 navigate 제거. 기존 버전의 자동 SKIP_WAITING 요청도 무시하여 첫 배포 중 기존 작성 탭을 보호한다.
- 업데이트 전 모든 MOA 탭에 작성 상태를 확인한다. 작성 중, 응답 없음, 이전 버전 탭이 있으면 대기한다. 확인한 탭은 전환 중 잠시 입력을 잠근다.
- 묵상 신규·수정 필드와 그림을 변경할 때 이 기기 localStorage에 계정별·작성 창별 저장. 재방문 시 명시적으로 이어쓰기. 서버 저장 성공 후 현재 초안만 정리하며 실패 때는 유지한다. 복제 탭은 별도 기록을 만들어 덮어쓰지 않는다.
- beforeunload/pagehide/visibilitychange에서도 저장을 시도하고 작성 중 닫기·새로고침에 브라우저 확인을 요청한다. 저장 용량/권한 실패는 표시한다.
- 동일 UID 사용자 객체 갱신으로 에디터를 초기화하던 구독 의존성을 UID로 변경한다. 자정의 날짜 자동 전환도 작성 중에는 적용하지 않는다.

임시저장은 기기·브라우저별이며 다른 기기에 동기화하지 않는다. 브라우저 데이터 삭제/저장 공간 거부 시 영구 보존할 수 없으므로 오류 표시와 이탈 확인을 제공한다. 이 기능 적용 전에 이미 유실된 메모는 남은 저장 기록이 없으면 복구할 수 없다.
