# 예배당 입장과 캐릭터 스튜디오

앱을 처음 열면 예배당 탭을 기본 선택합니다. 입장 전 로비에만 캐릭터 수정과 현재·오늘 입장 인원을 표시합니다. 입장하면 개인 인사와 현황을 숨기고 고요한 본당을 맨 위에 표시합니다. 로비로 돌아오면 캐릭터 수정과 현황을 다시 볼 수 있습니다. 방에 있는 다른 사람의 아바타는 계속 표시됩니다.

캐릭터 편집은 남성·여성 탭별 여섯 개씩, 총 열두 가지 샘플을 제공합니다. 이름은 보존하고 색상·스타일은 선택 후에도 개별 수정할 수 있습니다. 드래그(마우스/터치), 회전 버튼, 키보드로 조작 가능한 각도 슬라이더, 정면 보기 버튼으로 앞뒤를 확인합니다. 회전 각도는 편집 미리보기에만 적용됩니다.

남성형은 넓은 어깨와 짧은 머리, 여성형 기본은 허리까지 내려오는 생머리/웨이브와 넓어지는 튜닉 실루엣으로 구분합니다. 기존 스타일 범위와 DB 스키마를 유지합니다. 같은 PixelAvatar 렌더러가 미리보기·샘플·본인·다른 접속자에 적용되어 저장된 모습이 일치합니다. 머리는 머리 관절에 붙어 기도 자세를 따라갑니다.

본당에서는 저장소의 public/audio/sanctuary-ccm.m4a를 GitHub Pages의 /MOA/audio/sanctuary-ccm.m4a에서 HTML audio로 반복 재생합니다. Firebase Storage 재생 주소와 대체 연결은 제거했습니다. 사용자가 제공한 128kbps AAC M4A 원본은 127,181,688바이트로 GitHub 파일 제한보다 커서, 전체 재생 길이와 스테레오를 유지하며 80kbps AAC로 변환했습니다. 헤더는 faststart로 앞에 배치해 전체 파일 다운로드 전 재생할 수 있습니다. 원본 파일은 저장소에 넣지 않습니다.

음원은 PWA 프리캐시와 초기 앱 다운로드에서 제외하며, 입장 전에는 preload=none이고 플레이어도 만들지 않습니다. 입장 시 초기 음량은 20%이고, 상단의 노래 재생·정지 버튼으로 제어합니다. 정지는 재생 위치를 처음으로 돌리고, 오류 후 재생 버튼을 누르면 재연결합니다. 하단의 음악 카드는 제거했습니다. 자동재생이 차단되면 재생 버튼을 누르도록 안내합니다. 로비 복귀나 탭 이탈 시 pause 후 src를 해제하고 load하여 전송과 재생을 멈춥니다. 일반 묵상 화면의 오늘 찬송 추천은 기존 목록을 유지합니다.

검증: 성별별 샘플 개수·프로필 유효성·이름 보존·성별 실루엣 단위 검사, 로비/본당 노출·회전 조작 검사, 반복재생/낮은 음량/자동재생 차단/음량 조절/종료 정리 검사, 실제 Auth+DB 에뮬레이터 두 계정 간 외형 저장·동기화, 모바일/PC 캡처.


## 프로필과 예배당의 공용 아바타

프로필의 기존 사진 업로드·이름·소개 편집을 공용 3D 아바타 편집으로 대체합니다. 예배당과 프로필 모두 로그인한 기본 계정 UID의 sanctuary/avatars/{uid}를 사용합니다. 활동 AI 아이디를 바꿔도 다른 사람의 아바타 경로에 쓰지 않습니다. 사진 프로필이나 작성자 스냅샷을 별도 덮어쓰지 않고, 기존 기록 목록과 콘텐츠 작성자 정보는 유지합니다.

AvatarEditor는 두 진입점에서 동일한 남녀 샘플·팔레트·회전 UI를 제공합니다. useSanctuaryAvatar는 캐릭터 구독과 저장만 담당하여 프로필 열기가 예배당 입장·방문 수를 늘리거나 공동 기도 데이터를 구독하지 않습니다. 저장 실패 시 편집창과 입력을 유지하고, 계정 변경/로그아웃 시 이전 계정의 화면과 구독을 정리합니다.

검증에는 프로필 저장 경로·불러오기·샘플·실패 보존·계정 교체·비로그인 보호 검사와, 실제 Auth/RTDB 두 계정 브라우저에서 예배당 → 프로필 → 아바타 편집 → 예배당 및 상대 화면 동기화 검사를 포함합니다.


## 모아 브랜딩

앱 표시 이름과 설치 이름은 모아로 통일합니다. 모아는 묵상·선교·교제의 약어라는 사용자 설명을 따르며, 앱 소개에도 이 의미를 반영합니다. 따뜻한 크림색 석재, 붉은 지붕, 금빛 십자가를 담은 3D 복셀 예배당 아이콘을 사용합니다. 일반 앱 아이콘은 192/512px PNG, Android maskable 아이콘은 안전 영역에 여백을 둔 별도 512px PNG, iPhone 홈 화면 아이콘은 180px PNG, 브라우저 아이콘은 32px PNG입니다. 파일명에 chapel-v1을 포함해 이전 M 로고와 주소를 구분합니다.

기존 PWA id(/MOA/), scope, 시작 주소와 Firebase/로컬 저장 키는 유지합니다. HTML 제목·설치 manifest·Apple 앱 이름·탐색 접근성 이름·예배당 표기를 함께 변경하고, manifest 선언 크기와 실제 PNG 크기를 확인합니다.


## 두 언어 대조 읽기와 본문 끝 묵상

말씀 화면의 대조 읽기에서 한국어·영어(WEB)·일본어 중 서로 다른 두 언어를 선택합니다. 동일한 날짜/성경 범위인지 검증하고 장·절 키로 짝을 맞춰 원문 아래에 대조 본문을 표시합니다. 대조 설정은 기기에 보관하며, 끄면 두 번째 언어를 요청하지 않습니다. 누락·오류·다른 범위는 다른 언어로 대체하지 않고 재시도를 안내합니다. 캐시 불러오기 실패/누락은 메모리 캐시에서 제거해 재시도가 실제로 다시 불러오게 합니다.

본문 끝의 묵상하기는 선택한 구절을 유지하고 작성 제목으로 스크롤·포커스합니다. 두 언어로 선택한 인용문은 작성 시작/임시저장 복원/기존 글 수정 시 스냅샷으로 보존하여 비동기 본문 로딩이나 현재 대조 설정이 저장된 인용을 덮어쓰지 않습니다. 새 구절을 직접 선택하면 현재 본문으로 다시 인용합니다.

검증: 대조 본문과 범위 일치·누락/오류·설정 기억·두 언어 저장·기존 인용 보존 단위 검사, 실제 배포 KO/EN/JA 캐시를 이용한 360/768/1440px 브라우저 대조 읽기·본문 끝 작성 진입/포커스·새로고침 임시저장·누락 후 재시도 검사.


## 픽셀 예배당 시작 화면

HTML에 가벼운 예배당 그림과 무기한 준비 바를 먼저 표시해 JS 다운로드 전 빈 화면을 줄입니다. React가 준비되면 같은 그림과 잔잔한 반짝임·진행 바·계정 확인/말씀 펼치기/나눔 준비 단계로 이어집니다. 진행률은 로그인 상태와 활동 아이디 확인, 실제 첫 말씀/묵상/공개 나눔 콜백을 기준으로 계산합니다. 첫 데이터 확인은 기존 구독에서 신호만 받아 추가 요청을 만들지 않습니다. 계정별 데이터 소유자를 대조해 이전 계정의 준비 상태를 재사용하지 않습니다.

구글 로그인 버튼은 기존 로그인·활동 해제 순서를 그대로 실행하며 로딩 화면만 함께 표시합니다. 취소/오류 때 앱의 로그인 오류를 보여주고, 같은 계정으로 재로그인해도 완료될 수 있습니다. 준비가 끝나면 인위적 최소 대기 없이 닫습니다. 느릴 때 1.6초 뒤 먼저 둘러보기를 제공하고, 최대 8초 뒤에는 화면 가림만 해제합니다. 인증이나 데이터 요청을 취소하거나 로그아웃하지 않으며, 이후 도착한 데이터는 계속 반영합니다.

움직임 줄이기 설정에서는 반짝임과 예배당 움직임을 중단합니다. 360/768/1440px, Google 성공/취소, 느린 연결의 수동/자동 진입, JS 실행 전 화면을 브라우저에서 검증합니다.


### 언어 중복 선택으로 변경

별도 대조 읽기 모드와 두 번째 언어 선택란을 제거했습니다. 말씀 언어 메뉴의 체크 항목으로 한국어·영어(WEB)·일본어를 여러 개 고를 수 있으며, 한 언어는 반드시 남습니다. 첫 기본값은 한글+영어이고 세 언어도 동시에 표시·인용할 수 있습니다. 새 선택 형식(v2)을 기억하며 기존 대조 모드 끄기 설정 때문에 기본 한글+영어가 사라지지 않게 합니다. 본문 끝 묵상하기, 구절 인용 스냅샷, 누락 번역 재시도는 유지합니다.

## 외형 랜덤 선택

캐릭터 미리보기 오른쪽 위의 랜덤 버튼은 현재 선택한 성별과 입력한 이름을 유지하고 피부·머리색·옷·바지·머리 모양·상의·액세서리를 다시 조합한다. 직전 모습과 같은 결과가 나오면 옷 색상을 바꿔 매번 다른 미리보기를 보여준다. 저장 전에는 편집기 안의 미리보기만 변경하고, 저장을 누르면 기존 프로필/예배당/피드의 공용 아바타 설정으로 반영한다. 저장 중에는 랜덤 버튼을 잠근다.

검증: 유효한 외형 범위와 이름·성별 보존, 같은 난수의 반복에도 외형 변경, 저장 전 미반영과 저장 중 버튼 잠금 테스트. 모바일 Chromium에서 세 번 연속 랜덤 선택 후 실제 Auth+Database 저장 및 비로그인 독자의 아바타 동기화를 확인했다.
