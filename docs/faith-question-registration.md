# 질문·답변 등록 실패 수정

질문과 답변 생성 시 화면은 과거 활동 아이디인 activityId를 전송했지만 공개 faithQuestions 및 faithQuestionAnswers 규칙은 해당 필드를 허용하지 않았다. 빈 문자열인 경우에도 필드가 존재하므로 $other 검증에 걸려 PERMISSION_DENIED로 저장이 실패했다. 기존 규칙 테스트는 이 필드 없는 단순 예제를 사용해 화면의 실제 요청과 차이가 있었다.

두 생성 요청에서 activityId를 제거했다. 작성자는 Firebase 인증 UID와 작성자 이름으로 식별하며 기존 데이터 읽기 및 작성자별 수정·삭제 권한은 유지한다. 데이터 권한을 넓히지 않았다. 실패 시 작성 내용이 유지되는 기존 동작도 유지한다.

회귀 검증은 실제 MeditationApp에 비어 있지 않은 과거 activityId prop을 주고 Auth/DB 에뮬레이터에 연결한다. 두 브라우저 계정으로 질문 생성, 다른 계정의 조회·답변, 저장 데이터에 activityId가 없는지, 작성자 수정과 질문·답변 동시 삭제를 확인한다. 규칙 테스트도 기존 요청 형식의 거절과 정상 형식의 수락을 함께 검증한다. 이 브라우저 검사를 지속 통합의 기존 두 계정 에뮬레이터 단계에 추가했다.
